## Not fixed: your call or a bigger change

### High

**A. Anyone can fill the challenge pool and lock everyone out of signed requests.** `Limits.swift:131-136`, `HTTP.swift:271-282`.
- **How:** the cap is 10 outstanding challenges per IPv6 /64 and 10,000 overall. About 1,000 /64s, which is less than one /48 from a free tunnel broker, can keep it full at roughly 33 requests a second.
- **Result:** `/attest`, `POST/DELETE /activities` and `/diagnostics` all return 503 for everyone for as long as the flood lasts.
- **Options:**
  - Stateless HMAC challenges: random + expiry + HMAC. The assertion counter already stops replays; keep a used-set only for `/attest`.
  - The smaller option: a per-/48 cap, such as 64 outstanding.

  This is a design change to the attest protocol, so I left it.

**B. Lock Screen "At Station" when the server doesn't have the countdown.** This is #1's other half. With following trains but **no server registration**, the one stale redraw still lands inside the hold. That happens with no App Attest, a failed registration, or the server down. The app is suspended, so nothing moves it on until the next update.
- **Fix:** also use train + 15 s as the stale date when `ActivityPush` records `serverBacked == false`. The catch is that registration completes after the first `content()` is built, so the first train of a fresh countdown would lose its "At Station" label.
- **Tradeoff:** showing "At Station" on time versus never getting stuck.

### Medium

**C. Phones reading the MTA directly also take an empty feed as fresh.** `TrainService.swift:203`: `SubwayFeed.made(data).map { … } ?? false`.
- **Fix:** change it to `?? true` and throw `.malformed` in `SubwayFeed.arrivals` when there's no header.
- **Why I left it:** I didn't trace what the board does when *every* own feed is "missing" (`filling` becomes nil, and then?), so I didn't risk it. #2 covers the relay path, which most phones use.

**D. Widget and planner disagree on cross-platform change time.** `Change.swift:431-433` counts 0 s across the platform; `TimedPlanner.acrossSeconds` counts 60 s. The Transfers widget can pair an R arriving at 8:10:00 with a D leaving at 8:10:00 and count down to it, while New Trip says you'd miss it.
- **Fix:** use one constant in both.
- **Why I left it:** it changes which connections the widget shows, so it's your call.

**E. Walking map loops run in the background.** `WalkingView.swift:244-274`. A 0.25 s follow loop and a 3 s train loop keep running with the screen off during a walk. That's battery.
- **Fix:** gate them on `scenePhase == .active` and call `startOver()` on return.

**F. Cross-street reverse geocoding goes out in bursts.** `WalkingDirections.swift:261-286`.
- **How:** up to 24 `MKReverseGeocodingRequest`s go out back to back, again after every re-route, and two overlapping calls for the same crossing both miss the cache.
- **Result:** it can hit Apple's throttle; misses are cached for 5 min, so the signs go blank.
- **Fix:** space the requests about 1.2 s apart, keep in-flight entries so overlapping calls share one lookup, and don't clear names on small moves.

### Low

**G. Two trains due at the same second lose one.** `Countdown.swift:151` filters with `$0.time > target.time`; it should be `>= … && $0 != target`. `CountdownSync.swift:84` then hides that train on widgets.

**H. Widget "then N min" labels can read up to 59 s too high.** `TimelinePlan.swift:32-38`: entries are `now + 60·k`, not lined up with train times.

**I. "At Station" is cut short after a move-on.** `Countdown.swift:143-146`: `same` is nil when `trip == ""` (always true after `movedOn`), and `next` searches only `time > now`. A refresh 5 s into the hold jumps to the next train.

**J. Relay copies expire when a poller pass runs long.** `FeedRelay.swift:45`: `maxAge = 2·interval + 10` is measured from the start of each refresh, and a pass over about 40 s makes `/feeds` return 502 every cycle. Phones fall back to the MTA, so this costs load, not correctness.

**K. A slow device clock delays stale-feed detection by the amount it's slow.** `SubwayFeed.swift:85-88`.

**L. `/diagnostics` reads up to 512 KB before any authentication.** `HTTP.swift:404`.
- **Fix:** check that the key header names a known key before collecting the body.

**M. No idle timeout on server connections.** `ServerMain.swift:109`.
- **Fix:** set `HTTP1Channel.Configuration(idleTimeout: .seconds(30))`.
- **Risk now:** low, since only cloudflared reaches 127.0.0.1.

**N. IPv4 NAT users share 10 keys and 10 challenges a day.** For example an office, a café, or carrier NAT. `Config.swift:48-49`.

**O. First run:**
- **Reminder never scheduled:** the summary shows "Reminder · Weekdays 8:15" even when Commute was skipped with no train, so nothing is scheduled (`FirstRun.swift:786` against `:337`).
- **Saved places lost:** Run Setup Again clears Home and Work right away (`AppTabs.swift:59-64`). If the app is killed mid-setup, the places are gone and setup is marked done again.

**P. New Trip:**
- **Home/Work not saved:** choosing Current Location before the first fix saves nothing, with no message (`NewTripView.swift:1285`).
- **Return cancels a lookup:** pressing Return during a place lookup cancels it, and nothing gets picked (`NewTripView.swift:2023-2034`).

**Q. Router heuristic can overestimate.** The fixed-cost driveway and path arms (2 s, 0.5 s) cost less than the estimate (`WalkRouter.swift:490-548`), so A* with an early stop can return a route a few seconds worse.

## Checked and found sound

- **App Attest:** the cert chain is checked to a pinned root, along with the nonce, key ID, rpIdHash, aaguid, counter-0 on attestation, and a monotonic counter in one conditional `UPDATE`.
- **Server parsers:** CBOR has a depth cap of 8, bounds checks on every length, and refuses duplicate keys and trailing bytes.
- **SQL:** every query binds its parameters.
- **Diagnostics:** the file name comes from a fixed set of kinds, files are 0600, and disk use is capped at about 512 MB.
- **Logs:** they hold only token prefixes and hashed IPs and keys.
- **APNs key:** the `.p8` is git-ignored and has never been committed.
- **Protobuf reader:** no crash paths on truncated or malformed feeds.
- **Timetable times:** DST and GTFS >24:00 handling is correct.
- **Calendar use:** the only Calendar use pins America/New_York.
- **Walk stores:** both SQLite stores open read-only and immutable, each used only inside its own actor, with statements finalized and blob lengths checked.
- **WalkDemos:** fully inside `#if DEBUG`, including its hook in `LeewayApp`.
- **Walk concurrency:** `WalkSession`, `ActiveWalk` and `CompassHeading` are main-actor, and `stop()` cancels their tasks.
- **Privacy:** contacts stay on device, and only coordinates go to `/routes`.
- **Share extension:** link parsing is bounds-safe and pages are capped at 200 KB.
- **Deep links:** they're limited to `Nearby.allowURL`.
- **Background tasks:** registration and completion, and the diagnostics opt-in gating, are correct.
